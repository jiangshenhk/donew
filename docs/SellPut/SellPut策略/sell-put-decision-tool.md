# Sell Put 综合决策工具 — 设计思路

> 当前模块版本：`2.1.3`。报告字段与内容格式的唯一规范源为 [`docs/tools/sell-put-decision/设计_综合卖Put决策.md`](../../tools/sell-put-decision/设计_综合卖Put决策.md)。
> `sell-put-decision-v1.7.15` 是加入 Delta / Bid / Ask 合约执行硬门槛前的回退基线。

## 核心特性

| 特性 | 说明 |
|---|---|
| **四维数据聚合** | 行情快照 + 相关新闻 + 共享K线相似度引擎 + 前台期权截图 OCR |
| **单票风险调整** | ATR%/趋势/跌幅自动上调风险分，代码层执行，不受 AI 输出偏差影响 |
| **期权温度参与规则版** | IV/HV、IV Rank/Percentile、Expected Move、Put/Call结构会调整风险分和最低结论 |
| **事件风险检查** | 代码层扫描24小时新闻；AI只能引用新闻中明确出现的事件，不得凭训练记忆补未来日期 |
| **完整性门槛** | 行情、新闻、K线、期权温度或具体合约数据缺失时，只输出预检查，不调用 AI、不输出卖 Put 结论 |
| **共享判断核心** | 期权温度、市场风险、K线调整、新闻事件和完整性规则集中在 `_lib/sell-put-decision-core.js` |
| **复用独立工具** | 直接调用 `put-rating.js` 的卖Put温度判断和 `news-summary.js` 的24小时相关新闻判断，不另写简化版 |
| **共享K线引擎** | 直接调用 `report.js` 的结构化分析函数，复用形态匹配、历史样本概率和ABC/2B判断 |
| **六节结构化报告** | 综合结论 → 市场环境 → 期权温度解读 → K线技术信号 → 综合卖Put建议 → 未来关注清单 |
| **结论措辞明确** | 可卖Put / 谨慎卖Put / 暂不卖Put，不会输出股票买卖建议 |
| **标准功能** | 新窗口打开、下载 HTML、保存图片（html2canvas）、图片分享、历史报告导入对比 |
| **报告自动恢复** | 最近一次报告自动从浏览器 localStorage 恢复，支持离线查看 |
| **OCR 识别** | 用户点击按钮后，由前端 Tesseract.js 在当前浏览器本地识别 Barchart 截图并填入字段；生成接口不接收图片 |
| **期权参数前置门槛** | 用户必须先点击“自动获取期权参数”并成功填入当前标的数据；“手工修改”链接用于展开截图识别和逐项校正 |
| **完整截图映射** | 对应 Barchart Options Overview 的 IV变化、IV高低点及日期、Expected Move DTE、Expected Range、Put/Call、成交量和持仓量 |
| **补充说明兼容** | 合约字段留空时，仍可从补充说明中的行权价、Delta、Bid、Ask 和到期日自动提取 |
| **结论一致性** | AI结论不得比规则风险底线更激进；无标准结论或冲突时自动使用规则版 |
| **合约执行硬门槛** | Delta、Bid、Ask、价差、严格安全行权价均由代码判断；失败时禁止自动下单 |
| **统一章节格式** | 所有报告章节固定使用“标题 → 本节结论 → 核心指标 → 详细要点 → 风险提醒”，并由后端补齐标准样式类 |
| **完整规则版** | AI不可用或结论冲突时，规则版仍展示K线相似度/历史样本、24小时相关新闻、期权温度和合约安全垫 |
| **输出安全** | AI HTML 在进入报告前移除脚本、事件属性和危险链接 |

## 1. 为什么需要这个工具

卖 Put 不是单一维度的判断。好的卖 Put 决策需要同时考虑四个维度：

```
                    ┌─ 市场环境（大盘情绪、VIX、利率、地缘）
                    ├─ 新闻事件（财报、FOMC、非农等近期风险）
卖Put综合判断 ──────┼─ 技术面（K线趋势、ATR波动、支撑阻力）
                    └─ 期权温度（IV/HV溢价、恐慌程度、权利金价值）
```

原来的四个工具**各自独立**，用户需要手动在不同页面间切换、复制结论、脑补关联。这个工具的目标是**一次生成，四维合一**。

## 2. 核心设计原则

### 2.1 数据维度不是越多越好，是越结构化越好

不是把四个数据源扔进 prompt 就完事。每个数据源需要：
- **结构化提取**：新闻扫描事件风险、K线计算技术指标、行情快照算风险分
- **量化结论**：不是"感觉不对"，而是给出具体的数字（风险分、ATR%、安全垫%）
- **可追溯**：每个结论后面都有数据锚点

### 2.2 完整性门槛 + 代码判断 + AI 综合，三层决策

```
完整性门槛                 代码层（规则引擎）                  AI 层（综合判断）
┌──────────────────┐      ┌─────────────────────┐          ┌──────────────────────┐
│ 行情/新闻/K线     │      │ 市场风险评分（大盘）  │          │ 1. 解读评分含义       │
│ 期权温度/具体合约 │ ──→  │ + 单票风险调整（K线） │  ──→    │ 2. 综合四个维度       │
│ 缺失则仅预检查    │      │ + 事件风险扫描（新闻） │          │ 3. 生成格式化报告     │
└──────────────────┘      └─────────────────────┘          └──────────────────────┘
```

**规则引擎负责**：客观计算、不可被 AI 跳过
- 市场风险评分（VIX、QQQ、10Y、DXY 等大盘指标）
- 单票风险调整（ATR%、20 日趋势、5 日趋势）
- 事件关键词扫描

**完整性门槛负责**：禁止在证据不足时给出貌似完整的交易结论
- 关键行情至少包含标的、QQQ、SPY、VIX、10Y、DXY，且价格和涨跌幅均有效
- 必须取得标的 K 线和近期新闻
- 期权温度必须包含 IV、HV，以及 IV Rank / IV Percentile 之一
- Expected Move 与 Expected Range Low 必须为有效正数
- 具体合约必须包含行权价、Delta、Bid、Ask 和未来有效到期日
- 任一项缺失时，返回 `report_mode: precheck`，AI 不调用，风险分不作为决策输出

**AI 负责**：分模块解读、综合证据、提供结构化详细论证
- 读评分背后的含义（不是念分数）
- 结合四个维度的信息给出判断
- 分别返回市场、K线、期权 JSON；最终可视化报告由固定代码模板组装
- 只能解释已取得的新闻事件，不得猜测未来事件日期

报告不得只有六个标题和摘要。每个模块的必填字段、六节最低详细度、颜色语义、降级行为和验收清单统一维护在 `设计_综合卖Put决策.md`，修改本设计文档时不要复制另一套不同规则。

### 2.3 风险评分是硬约束，不是建议

三层风险判定：

| 风险分范围 | 盘面判定 | 含义 | 代码强制 |
|---|---|---|---|
| < 6.2 | 可卖Put | 市场平稳，仍需期权与事件数据确认 | 是，作为最低风险底线 |
| 6.2 - 7.5 | 谨慎卖Put | 有风险信号，需减仓 | 是，AI不能降为可卖Put |
| ≥ 7.5 | 暂不卖Put | 风险大于收益 | 是，AI不能覆盖为更激进结论 |

风险分通过 Hero 区域 chip 展示，AI prompt 也收到调整依据。AI可以基于期权温度和新闻给出更谨慎的结论，但不能低于代码层确定的风险底线；冲突时整份AI结果不采用，改用规则版。

尾部风险灯号是启发式风险提示，不是经过历史校准的“大跌概率”。AI可以给出更谨慎的结论，但不得给出比规则风险底线更激进的结论。

### 2.4 具体合约执行硬门槛（`evaluateOptionContract`）

完整报告生成后，代码再判断这张具体 Put 是否具备进入自动下单前复核的资格：

| 项目 | 有利环境 | 谨慎环境 | 不利环境 |
|---|---:|---:|---:|
| Delta范围 | 0.10 - 0.25 | 0.08 - 0.15 | 直接阻断 |
| Bid / Ask | 必须为有效正数，Ask ≥ Bid | 同左 | 直接阻断 |
| 价差 | `Ask-Bid <= max($0.10, Mid×15%)` | 同左 | 直接阻断 |
| 行权价 | `Strike <= min(现价-ATR×sqrt(DTE), Expected Range Low)`，ATR倍数最低为1.5 | 同左 | 直接阻断 |

Delta 使用绝对值判断，允许输入 `-0.15` 或 `0.15`。Delta 低于建议下限不会直接阻断，但会标记为收益效率偏低；高于上限属于硬阻断。ATR安全价按 DTE 调整，避免 5 天和 45 天期权使用同一条 1.5×日ATR安全线。

收益率同时展示两种口径（不计手续费）：

```text
现金担保年化 = Mid / Strike × 365 / DTE
净接货成本年化 = Mid / (Strike - Mid) × 365 / DTE
```

后续自动化接口必须读取 `execution_gate.approved`。只有它为 `true` 时，才允许进入券商限价单模块；AI文字结论不能覆盖该字段。

## 3. 评分体系详解

### 3.1 第一层：市场环境评分（`marketRisk`）

基准分 **5.0**。这个起点仍然偏保守，但不会因为一条轻微信号就自动进入“谨慎”区。以下事件触发加分（分数越高 = 风险越大）：

| 大盘信号 | 加分 | 含义 |
|---|---|---|
| VIX 日涨 >8%，或 VIX >20 且日涨 >5% | +1.2 | 恐慌情绪飙升；单纯5%左右日波动不再触发 |
| 10Y 收益率涨 >1% | +0.7 | 利率压制科技股 |
| DXY 涨 >0.3% | +0.6 | 美元走强，风险资产承压 |
| QQQ / SPY 跌 >1% | +0.9 | 大盘明显走弱 |
| SMH / SOXX 跌 >1% | +0.7 | 半导体领跌 |
| BTC 跌 >2.5% | +0.5 | 风险偏好恶化 |
| IWM 跑赢 SPY | -0.2 | 防御轮动（其实是好事） |
| 标的自身跌 >3% | +0.6 | 个股加速下跌 |

### 3.2 第二层：期权温度调整（`adjustRiskWithOptionMetrics`）

规则版必须看期权溢价，不允许只用市场风险分做卖 Put 判断。

| 期权信号 | 调整 | 含义 |
|---|---:|---|
| IV Rank ≥80、IV Percentile ≥85，或 IV-HV ≥10个百分点 | -0.3 | 溢价补偿较好，但不覆盖市场硬风险 |
| IV Rank/Percentile低温，或 IV < HV | +0.4 | 权利金补偿不足 |
| Put/Call Vol Ratio ≥1.5 / ≥2.5 | +0.5 / +0.8 | Put成交明显拥挤，可能是防守盘 |
| Put/Call OI Ratio ≥1.2 / ≥1.8 | +0.3 / +0.6 | Put持仓结构偏防守 |
| Expected Move ≥8% / ≥12% | +0.4 / +0.7 | 到期前预期波动偏大 |

期权温度只能改善“权利金是否值得”的部分，不能让不利市场或合约门槛失败变成“可卖Put”。

### 3.3 第三层：单票 K线调整（`adjustedRisk`）

大盘评分只反映宏观环境。个股自身的趋势和波动也需要纳入：

| K线信号 | 加分 | 适用场景 |
|---|---|---|
| ATR 占比 >8% | +1.0 | 极度波动（如 INTC） |
| ATR 占比 >6% | +0.5 | 波动偏高 |
| 20 日跌幅 >20% | +1.0 | 自由落体式下跌 |
| 20 日跌幅 >10% | +0.5 | 持续走弱 |
| 5 日跌幅 >5% | +0.3 | 短线加速下跌 |
| 历史相似样本偏空概率 ≥60% | +0.5 | 历史统计偏空 |
| 历史相似样本偏空概率 ≥75% | +1.0 | 历史统计显著偏空 |
| 偏空形态匹配度 ≥75% | +0.5 | 当前形态存在高可信偏空结构 |

**为什么不减分（利好不加分）？**
卖 Put 是风险定价工具，我们的目标是识别风险，不是找"完美时机"。利空信号需要拉响警报，利多信号保持默认为好。

### 3.4 调整示例

INTC（2026-07-20）：
```
原始评分: 5.0 + 0.7(10Y↑) = 5.7 → "可卖Put"
  +1.0 (ATR 9.18% >> 8%)
  +1.0 (20日跌 26.8% >> 20%)
  +0.3 (5日跌 5.2% > 5%)
= 8.2 → "暂不卖Put"
```

## 4. 数据流架构

```text
前台准备: 点击“自动获取期权参数” → /api/barchart-overview → 填入当前标的默认 metrics
可选校正: 点击“手工修改” → 浏览器本地 OCR screenshot 或逐项输入
用户提交: symbol / metrics / notes（不提交截图）
  │
  ├─→ prepare：并行读取行情、新闻、期权参数 → reportId
  │
  ├─→ 三个后台模块并行 ─────────────────────────┐
  │   ├─ analyze-market：市场与新闻              │
  │   ├─ analyze-kline：K线共享引擎与技术统计     │
  │   └─ analyze-option：期权温度与具体合约       │
  │       前端每2秒调用 status，避免长连接超时     │
  │                                              │
  ├─→ 代码层处理 ─────────────────────────────┐  │
  │   ├─ analyzeKlineStructure() ← 与K线工具同源│  │
  │   │   ├─ 经典形态规则+DTW图形匹配          │  │
  │   │   ├─ 5年历史相似样本后5根K线统计       │  │
  │   │   └─ ABC/2B结构与趋势路径              │  │
  │   ├─ computeKlineStats()   ← 共享引擎K线   │  │
  │   │   ├─ SMA5/10/20/50                    │  │
  │   │   ├─ ATR(14)                          │  │
  │   │   ├─ 形态检测（十字/吞没/锤子等）        │  │
  │   │   ├─ 支撑/阻力位                       │  │
  │   │   └─ 1/5/20日涨跌幅                    │  │
  │   ├─ marketRisk()         ← 行情快照        │  │
  │   ├─ adjustedRisk()       ← 风险分+K线      │  │
  │   └─ scanEventRisks()     ← 新闻            │  │
  │                                              │
  ├─→ finalize：使用实际ATR重算合约门槛           │
  ├─→ assessDecisionReadiness() 完整性门槛       │
  │   ├─ 缺失 → 卖Put预检查（不调用 AI）          │
  │   └─ 完整 → AI Prompt ──────────────────────┘
      ├─ 规则引擎给出不可放宽的底线
      ├─ 三模块JSON提供详细论证
      ├─ 固定模板回答三问并组装六节报告
      └─ 视觉规范（badge/tag/data-item/bullet-list）
```

## 5. 输出报告结构

```
<section class="hero-judgement">   ← 综合结论（三问+事件风险+量化数据）
<section class="section">          ← 市场环境（大盘 data-item + bullet-list）
<section class="section">          ← 期权温度解读（tag + highlight + bullet-list）
<section class="section">          ← K线技术信号（flex-between + table + bullet-list）
<section class="section">          ← 综合卖Put建议（action bar + 编号风险 + 警告框）
<section class="section">          ← 未来关注清单（两列信号 + 改变判断标签）
<details>                          ← 实时行情快照表格
```

## 6. 与其他工具的关系

这不是替换，是**聚合层**，骑在现有基础设施之上：

- `stockprice/` → 行情底座（数据同上）
- `jin10news/` → 新闻底座（数据同上）
- 独立页面 → 用户仍然可以单独使用原有三个工具
- 综合决策 → 新增的"一键生成"入口

核心规则文件：
- `vps-backend/src/api/_lib/sell-put-decision-core.js`：无网络依赖的可复用判断核心
- `vps-backend/src/api/sell-put-decision.js`：读取结构化数据、启动三个后台模块、统一裁决并组装报告
- `vps-backend/src/api/report.js`：导出 `analyzeKlineStructure()`，共享形态和历史统计逻辑
- `vps-backend/src/api/put-rating.js`：导出 `analyzePutRatingSnapshot()`，共享市场/温度判断
- `vps-backend/src/api/news-summary.js`：导出新闻读取、相关性筛选和事件扫描
- `vps-backend/src/routes/ai.js`：生产路由与安全校验边界
- 模块通过后台任务执行，前端轮询状态；不再依赖Vercel函数时限或浏览器长连接
- 综合决策只使用 DeepSeek，不调用 GPT；接口同时返回各阶段耗时，便于定位慢点
- 其他工具需要复用规则时应导入核心函数，不要在 API 文件中复制一套评分规则
